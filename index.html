The Six Warning Signs

Key heuristics analyzed by this tool according to the EWB Cybersecurity project syllabus.

CHECK 01

@ Symbol in URL

Text before @ is treated as authority/login metadata and ignored by browsers; the real destination is after the @.

Honest limit: Rare in normal links, but possible in basic HTTP authentication.

CHECK 02

Very Long URL (> 100 chars)

Excessively long paths and queries can push malicious destination domains off-screen on mobile devices and narrow address bars.

Honest limit: Many legitimate tracking links or deep search URLs are naturally long.

CHECK 03

IP Address Hostname

Legitimate organizations use trusted domain names. Bare numeric IPv4 addresses often obscure owner identity.

Honest limit: Local routers, intranet services, and developer test environments use IPs.

CHECK 04

Many Subdomain Segments

Stacking subdomains (e.g. paypal.com.verify.account.phish.invalid) tricks users into reading trusted brand names early.

Honest limit: Large enterprise networks and CDNs sometimes legitimately use multi-level subdomains.

CHECK 05

Punycode Marker (xn--)

Internationalized Domain Names (IDNs) can use look-alike Cyrillic or Greek characters to impersonate legitimate Latin domain names.

Honest limit: Millions of genuine non-English websites legitimately use IDN punycode.

CHECK 06

HTTP Instead of HTTPS

Plain HTTP traffic is unencrypted and vulnerable to intercept. HTTPS encrypts transmission, though HTTPS alone does not guarantee safety.

Honest limit: Over 90% of phishing sites today use HTTPS certificates.
